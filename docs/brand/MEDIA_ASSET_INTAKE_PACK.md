# Media Asset Intake Pack

Status: blank inventory and review template; **nothing in this document grants permission to publish an asset**.
Applies to: TPS and TIER websites, campaign landing pages and related public digital content.
Handling: keep original files and signed permissions in an access-controlled organisational drive. Commit only asset IDs and non-sensitive references to this repository.

## 1. Intake workflow

1. Assign a unique asset ID before editing or uploading a derivative.
2. Preserve the original file unchanged in the controlled source library.
3. Identify the actual institution, campus, event, date and rights holder.
4. Confirm licence/ownership and the exact channels, purposes and expiry covered.
5. For identifiable people, confirm documented permission; for minors, verify guardian consent and applicable safeguarding approval.
6. Remove unnecessary personal data from filenames, captions, metadata and public URLs.
7. Create web derivatives only after rights review; record dimensions, format, crop/focal point and optimisation.
8. Obtain an authorised approver's decision for the exact asset and intended use.
9. Recheck permission expiry/withdrawal and remove or replace assets promptly.

## 3. Non-negotiable review rules

- Official Tagore logos must be the exact approved source files. Never redraw, recolour, distort, crop into the mark or substitute them.
- Do not portray stock or AI-generated imagery as an actual Tagore campus, student, employee, event or facility.
- A public social-media post is not a licence to reuse the image.
- For identifiable minors, require documented guardian consent covering the specific website/channel and purpose, plus the institution's required safeguarding approval.
- Avoid publishing student full names, class/section, precise schedules, phone numbers, identity documents or sensitive personal circumstances.
- Adult staff/parent/visitor consent and photographer/agency/font/illustration rights must cover the intended use and derivative edits.
- Respect restrictions, attribution, territory, audience, expiry and withdrawal. Remove assets when permission is absent, disputed, expired or withdrawn.
- Alt text must describe the image's relevant purpose without guessing identities or exposing sensitive details. Decorative images should have empty alt text in implementation.

## 4. Web derivative checklist

- [ ] Original preserved unchanged in controlled storage.
- [ ] Correct institution/campus/event confirmed.
- [ ] Rights and permissions approved for the exact intended channel and purpose.
- [ ] Guardian consent and safeguarding approval recorded where required.
- [ ] No unnecessary personal data in image, filename, EXIF, caption or URL.
- [ ] Crop/focal point reviewed at mobile and desktop sizes.
- [ ] Responsive AVIF/WebP derivatives generated where supported; fallback retained as needed.
- [ ] Width/height or aspect ratio reserved to prevent layout shift.
- [ ] Descriptive alt text or decorative empty alt confirmed.
- [ ] File size, lazy loading and page weight checked.
- [ ] Approver, approval scope and review/expiry date recorded.
