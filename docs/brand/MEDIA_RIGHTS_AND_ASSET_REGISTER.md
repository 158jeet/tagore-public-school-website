# Media Rights and Asset Register

Status: governance template; no new photographs, videos, testimonials or identifiable-person media are authorised by this document.
Owner: Tagore Group media/content owner (to be assigned)

## Purpose

Ensure every image, video, logo, testimonial and downloadable creative used on either website is authentic, correctly attributed, technically optimised and supported by permission for the intended use. A file being available in a folder or on social media does not establish permission to publish it on the websites.

## Asset record

Create one record for every asset or logically identical derivative set.

| Field | Required content |
|---|---|
| Asset ID | Stable ID, e.g. TPS-PHOTO-0001 |
| File/path | Original controlled file path and derivative paths |
| Asset type | Logo, campus photo, classroom, event, staff portrait, student media, testimonial, PDF, video |
| Institution/location | Correct campus and location |
| Capture/source | Photographer, staff member, agency or original source |
| Capture date | Date captured or document issue date |
| People identifiable? | Yes / no / uncertain |
| Permission evidence | Signed release/consent reference, licence or ownership record |
| Permitted use | Website, print, social, campaign, internal only; list channels explicitly |
| Restrictions | Expiry, crop/alteration limits, attribution, territory, audience |
| Guardian consent | Required status/reference where a minor is identifiable |
| Approver | Authorised institutional approver |
| Alt text/caption | Accurate, contextual, non-identifying where appropriate |
| Technical status | Original / reviewed / optimised / published / withdrawn |
| Review/expiry | Next review or permission expiry date |

## Non-negotiable controls

1. Never redraw, recreate, recolour, distort or substitute official Tagore logos. Use the exact approved source file and preserve its aspect ratio and clear space.
2. Do not use a stock photograph or AI-generated image as if it depicts a Tagore campus, student, employee, facility or event.
3. For identifiable students, especially minors, obtain documented guardian consent and follow the institution's child-safeguarding and media policy. Consent must cover the specific public channels and purpose.
4. Do not publish student full names, class/section, contact details, precise schedules, identity documents or sensitive personal circumstances alongside media.
5. Staff, parents and adult participants must have documented permission for the intended use; respect withdrawal and expiry.
6. Verify agency, photographer and font/illustration licences, attribution requirements and derivative rights.
7. Do not treat a public social-media post as a reusable licence.
8. Remove or replace an asset promptly when permission expires, is withdrawn, cannot be verified or the depicted facility/event is no longer accurately represented.

## Recommended media workflow

- Keep an immutable original in a controlled source folder; generate web derivatives separately.
- Record the asset ID in page/content metadata or a media manifest.
- Generate responsive AVIF/WebP derivatives with correct dimensions and sensible compression; preserve the original.
- Write descriptive alt text for informative images; use empty alt text for purely decorative imagery.
- Avoid embedding personal data in filenames, EXIF metadata, captions or public URLs.
- Review image focus/cropping at mobile and desktop breakpoints.
- Check page weight, lazy loading and layout dimensions to avoid layout shift.
- Recheck the page after an asset is replaced or permission is withdrawn.

## Minimum publication checklist

- [ ] Correct institution, campus and event are identified.
- [ ] Original source and rights holder are known.
- [ ] Permission/licence covers the website and intended use.
- [ ] Guardian consent is documented where a minor is identifiable.
- [ ] No unnecessary personal or sensitive information is exposed.
- [ ] Caption and alt text are accurate and respectful.
- [ ] Logo artwork is the exact approved file, unchanged.
- [ ] Responsive derivatives, dimensions and performance are checked.
- [ ] Approver and review/expiry date are recorded.

If any item is unknown, do not publish the asset until the issue is resolved.
